# Clockworks Analytics

> Clockworks Analytics is a building-analytics company whose cloud platform performs automated fault detection and diagnostics (FDD) on HVAC and building systems. It ingests interval data from Building Management Systems through the Clockworks Connect gateway, runs a curated library of root-cause diagnostics, and quantifies each performance issue by avoidable energy cost and by energy, comfort and maintenance priority on a 0-10 scale. Its REST API is delivered through Azure API Management on rest.buildingsapi.net in four containers.

This file was generated by API Evangelist from Clockworks Analytics' own public documentation. Clockworks does not publish an llms.txt of its own, and publishes no OpenAPI, AsyncAPI, GraphQL SDL or Postman collection — the API reference is HTML only.

## APIs

- [Clockworks Base API](https://rest.buildingsapi.net/core-base): Clients, buildings, building types and variables, equipment, equipment classes/types/variables, points, point classes/types, engineering units, data sources, analyses, task records, task statuses and users. JSON:API-shaped responses. Authenticated with an Azure API Management subscription key in the `Ocp-Apim-Subscription-Key` header.
- [Clockworks Diagnostics API](https://rest.buildingsapi.net/core-diag): `POST /diagnostics` returns diagnostic records for a set of client IDs, building IDs, a date range and an analysis interval, including avoidable cost, energy/comfort/maintenance priorities and narrative fault notes.
- [Clockworks Key Performance Indicators API](https://rest.buildingsapi.net/core-kpis): `POST /AggregatedData` accepts a Kusto Query Language (KQL) expression plus a dataset list and returns server-side aggregations across the Clockworks datasets.
- [Clockworks Work Orders API](https://rest.buildingsapi.net/workorders): Task records created from diagnostic results, for synchronization to a CMMS. Bearer token from `POST /workorders/auth/token` using a clientId and clientSecret; the token is valid for 3599 seconds.

## Conventions

- Media types: request `application/json`, response `application/vnd.api+json`.
- Versioning is by HTTP header (`ApiVersion`, `ApiDocVersion`), not by URL path.
- Pagination is page-number based at a fixed 1,000 elements per page via `page[number]`, with `self`/`first`/`next`/`last` links carrying a server-side cache key so a traversal returns a stable snapshot.
- Sparse fieldsets via `fields[<ResourceType>]`, chainable across related resources.
- Verbs: GET simple retrievals, POST complex retrievals, PUT create, PATCH update, OPTIONS preflight.
- No idempotency contract, no published rate limits, no error-code reference, no webhooks or event surface.
